# Agent Guidelines

This document contains coding conventions and best practices for AI agents working on this codebase.

## Ruby Style Conventions

### String Literals

**Always use single quotes for string literals unless you need string interpolation or special symbols.**

- ✅ Good: `notice: 'Order placed successfully!'`
- ✅ Good: `validates :title, presence: true`
- ✅ Good: `"Hello #{name}"` (interpolation requires double quotes)
- ❌ Bad: `notice: "Order placed successfully!"` (no interpolation needed)

**Rationale:** This follows the Ruby style guide convention and makes it clear when string interpolation is being used. Single quotes are slightly more performant and indicate that the string is a literal value.

**When to use double quotes:**
- When you need string interpolation: `"Hello #{name}"`
- When the string contains single quotes that would require escaping: `"It's a great day"`
- When using special escape sequences: `"Line 1\nLine 2"`

**Files to check:**
- `app/controllers/**/*.rb`
- `app/models/**/*.rb`
- `app/services/**/*.rb`
- `test/**/*_test.rb`
- `test/**/test_helper.rb`
- `db/seeds.rb`
- `db/migrate/**/*.rb` (for any string literals, though migrations typically use symbols)
- Any other Ruby files

**Files that are exceptions (auto-generated or use different conventions):**
- `db/schema.rb` - Auto-generated by Rails, uses double quotes by Rails convention. Do not manually edit.
- ERB templates and HTML attributes may use double quotes - that's fine and expected.
- YAML fixture files also use double quotes for values, which is standard YAML syntax.
